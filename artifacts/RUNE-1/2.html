PanelLeftFraction is a user-settable [Range(0,1)] option. Any configured value below ~0.29 drops 1600x900 under 24px at runtime while a test pinned to the 0.30 default still passes — so the test reads the default from new OcrOptions(), and the runtime path carries the MinCellPx guard.

Output contract — why row Y, not list position

OcrTextPostProcessor.ExtractFromRowTexts drops any row whose normalised text is under 3 characters or contains no letter. So ItemNames is a filtered subset of rowYs:

Hence RuneRowKeys(int RowY, IReadOnlyList<RuneKey> Keys), filtered at snapshot construction to the rows whose RowY appears in matchedYPositions — the same key ExtractFromRowTexts retained. RowY stays on the record so RUNE-2 asserts the pairing rather than assuming it.

RuneKey also carries its normalised 32×32 sprite bytes (~3 KB), already computed on the way to the hash — without it RUNE-2's dashboard cannot render a newly discovered rune.

Fail-soft contract

A cell count of ≠5 can never occur — equal-fifths slicing of a fixed strip always yields exactly 5. The predicates that can fire, each logging once and yielding no keys for that row:

  • stripWidth < 5 × MinCellPx — degenerate strip or misconfigured PanelLeftFraction
  • rowHeights[i] < MinCellPx — band too short to hold a sprite plus its ring
  • rowHeights[i] > 3 × (stripWidth / 5) — two combination rows fused by the ≤10px band merge
  • border metric in the ambiguous band → treated as non-gilded and dropped

Bias is deliberate: a wrong key corrupts RUNE-2's "already carrying" set and produces actively wrong advice; a missing key only under-reports one row.
