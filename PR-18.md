Three user reports.

## 1. Gold was being thrown away

> "opulent is always with yellow color in it it is distinct, should be the easiest to recognize"

Correct, and the code discarded it. `DominantGlyphHueBucket` counted any pixel `IsIconInk` accepted, which includes **dark** ones (`v < 0.35`). Every rune's glyph is drawn in dark brown ink, which is saturated and sits at hue 30-45 — **the same 30-degree bucket as gold** — so brown outvoted the real colour everywhere.

The user's own catalog proves it: 45 sprites produced exactly **two** buckets, 1 and 9, with Opulent in bucket 1 alongside tidal, rebirth, moon, cold, ward, rage and fire. Purple only came through because purple ink is bright enough to beat the brown.

Now: only bright saturated pixels vote, "no tier colour" is a distinct answer from bucket 0, and the measurement runs on the 64px sprite rather than the 32px glyph — box-filtering to 32 desaturates edges, and the same rune counted 162 gold pixels in one row and 72 in another.

### What is deliberately NOT done

**Gold does not yet map to the gold tier's weight.** Reading a weight off a colour needs two things and only one holds: the colour must mean exactly one rune (it does — Opulent is the catalog's only gold tier), and it must read the same for the same rune every time (**it does not**). Scoring off it would make the same rune worth 3 in one row and 1 in the next — precisely the inconsistency this was meant to remove.

The fixture's same-rune hue assertion is **dropped rather than relaxed**, with the gap written down where it was: identity (the hash) is stable across rows, the measured colour is not.

## 2. Right-click marks the rune under the cursor

Default, as requested. `RegisterHotKey` takes virtual keys, not mouse buttons, so this is a low-level mouse hook. Two rules keep it out of the way:

- It acts only when the click is inside a rune the overlay is marking **and** the game is in front. Everywhere else the click passes through untouched.
- Only a click it acts on is swallowed, so the game does not also receive that one.

`Alt+V` still works. Configurable via `MarkCarriedMouseButton` (`right` / `middle` / `none`).

## 3. The strip is transparent and click-through where empty

It paints no background. Everything it does not draw stays chroma-keyed — both transparent and click-through — so the column occupies only the pixels it actually uses and the game keeps the rest of its left edge. Each icon carries a small backdrop so it stays readable.

## Not verified

The mouse hook cannot be exercised in the test host: whether Windows installs it, whether swallowing the click behaves in game, and whether right-click over a rune conflicts with anything PoE2 does there.
